# Excel parsing, spreadsheet QA, and agent benchmarks

Research cutoff: **2026-10-15**, client date (Asia/Hong_Kong). Findings use the latest accessible primary sources in this session; live repository pages are not historical snapshots. Paper version dates and repository announcements are distinguished below. No packages, benchmark suites, or enterprise deployments were tested locally.

## Recommendations

These are workload-based engineering recommendations, not a universal ranking:

- For Python value ingestion into Arrow/Polars, evaluate **fastexcel**, backed by calamine. For Python lists or pandas' calamine engine, evaluate **python-calamine**. Neither replaces a workbook fidelity layer. [fastexcel](https://github.com/ToucanToco/fastexcel), [python-calamine](https://github.com/dimastbk/python-calamine).
- For Python cell metadata, layout inspection, and supported workbook edits, use **openpyxl**; use its read-only mode for large reads and assess preservation before round-tripping complex files. [Tutorial](https://openpyxl.readthedocs.io/en/stable/tutorial.html), [optimized modes](https://openpyxl.readthedocs.io/en/stable/optimized.html).
- For SQL analytics on identified XLSX regions, use **DuckDB read_xlsx** with explicit sheet, range, header, and schema policies. Its range inference is not semantic table detection. [Excel extension](https://duckdb.org/docs/current/core_extensions/excel).
- For Java services, **Apache POI** is the strongest fit among the reviewed candidates: event APIs for reading, usermodel for editing, and a supported subset of formula evaluation. This is an ecosystem-fit judgment, not benchmark superiority. [Repository](https://github.com/apache/poi), [spreadsheet APIs](https://poi.apache.org/components/spreadsheet/).
- For data quality assurance, validate extracted tables with **Pandera** or **Great Expectations** and business-specific reconciliation rules. For natural-language question answering, retrieve cell-addressed evidence and execute calculations deterministically; investigate SpreadsheetLLM and SheetAgent as research approaches. [Pandera](https://github.com/unionai-oss/pandera), [GX Core](https://github.com/fivetran/great_expectations), [SpreadsheetLLM paper](https://arxiv.org/abs/2407.09025), [SheetAgent](https://github.com/cybisolated/SheetAgent).

## Four different jobs

| Layer | Output and success criterion | What it does not establish |
| --- | --- | --- |
| Raw workbook reading | Correct cell values, types, coordinates, formulas/caches and supported metadata; throughput and memory | Meaning of a header or table; correctness of an answer |
| Semantic table extraction | Table boundaries, header hierarchy, units, relationships and cell provenance | Fresh formula results or reliable business reasoning |
| Question answering (QA) | Correct evidence-backed answer and deterministic computation | Workbook editing or visual preservation |
| Quality assurance and editing evaluation | Data constraints, recalculated output checks, preservation checks, task success | General question-answering accuracy or fastest parser |

This taxonomy is a synthesis of the reader APIs, SpreadsheetLLM's table-detection/QA experiments, and the manipulation benchmarks cited below. The two meanings of “QA” must remain explicit in requirements and metrics.

| Tool | Verified capabilities | Important limits and practical fit |

| openpyxl | Reads/writes XLSX/XLSM and template variants; exposes cells and supported workbook structure. `data_only` selects cached results instead of formula strings. | Cached values are from the last calculation, not newly evaluated formulas. VBA preservation is not VBA editing. Read-only mode limits features; the tutorial warns that unsupported shapes may be lost on save. Good Python inspection/editing baseline after fidelity tests. | python-calamine | Python bindings to calamine; sheet values as Python objects; pandas integration from pandas 2.2. | By default `to_python()` skips empty leading rows/columns; use `skip_empty_area=False` where absolute grid alignment matters, and verify wrapper-specific exposure of metadata/formulas. | DuckDB Excel | SQL XLSX import/export, explicit ranges and type controls; XLS is unsupported. | Inferred range can stop at the first empty row; types are inferred from the first data row. `ignore_errors=true` can silently replace failed casts with NULL. Best used after locating a table. [Official extension docs](https://duckdb.org/docs/current/core_extensions/excel), [repository](https://github.com/duckdb/duckdb-excel). |
| Apache POI | HSSF/XSSF for XLS/XLSX, eventmodel reads, usermodel edits, SXSSF streaming output. | SXSSF is principally a writer, not the streaming reader. Full workbook models cost memory. Formula coverage is partial; inspect supported function names in the pinned runtime rather than relying on inconsistent counts in different documentation pages. [APIs](https://poi.apache.org/components/spreadsheet/), [formula support](https://poi.apache.org/components/spreadsheet/formula.html), [evaluation](https://poi.apache.org/components/spreadsheet/eval.html). |

## Semantic extraction and question answering

**Microsoft SpreadsheetLLM / SheetCompressor.** Paper v1: 2024-07-12; latest accessible v2: 2025-04-02. Its three compression stages use structural anchors, inverted indexes, and format-aware aggregation. Table detection and downstream question answering are separate experiments. The paper reports roughly 25x compression and 78.9% table-detection F1 under its own setup; these are neither parser throughput nor a current cross-system leaderboard. [Paper/version history](https://arxiv.org/abs/2407.09025).

The v2 QA evaluation contains **307 items from 64 spreadsheets**, tests search/comparison/basic arithmetic, and deliberately excludes composite operations. Table 4 reports 0.743 accuracy for GPT4-compress-FT. Compression can discard information; the paper describes retrieving and re-encoding relevant tables for downstream tasks. Treat the work as a representation/region-selection design, preserving access to original cells. [Full paper, sections 4.2 and 5.3](https://arxiv.org/html/2407.09025v2).

No Microsoft-owned SpreadsheetLLM implementation was verified in this search. Opening the guessed `microsoft/SpreadsheetLLM` URL failed; that alone does not prove absence. GitHub search returned unofficial implementations, and [Spreadsheet_LLM_Encoder](https://github.com/kingkillery/Spreadsheet_LLM_Encoder) explicitly describes itself as paper-inspired and warns against assuming reproduced metrics. Do not attribute those repositories to Microsoft or equate their output with the paper results.

**SheetAgent.** Official repository: Planner, Informer, Retriever; the Retriever requires Milvus. Public SheetRM release is approximately 60%: **25 spreadsheets and 180 tasks**, so paper-level reproduction is constrained by available data. Its cited experiments include SheetCopilot and table QA/fact-checking datasets. This is an agent framework, not a standalone XLSX parser or enterprise reliability certification. [Official repository](https://github.com/cybisolated/SheetAgent). Paper v1: 2024-03-06; latest accessible v3: 2025-03-03; repository identifies WWW 2025 oral acceptance. [Paper](https://arxiv.org/abs/2403.03636).

These illustrate why identical-looking “success” scores can depend on the harness and engine. Their results were not independently reproduced.

## Quality assurance and enterprise practices

The following is a recommended acceptance plan, synthesized from the cited limitations; it is not a claim that any reviewed project implements all of it.

1. **Preserve a cell-level evidence layer.** Keep original workbook identity/hash, sheet and absolute coordinates, typed values, formula strings and cached values separately. Record merged regions, number formats, hidden rows/sheets and table definitions when they affect interpretation. Retain originals alongside normalized tables. Coordinate trimming and inferred schema must be observable. [python-calamine behavior](https://github.com/dimastbk/python-calamine), [openpyxl flags](https://openpyxl.readthedocs.io/en/stable/tutorial.html).
2. **Make table and type decisions explicit.** Prefer declared tables or configured regions; use semantic detection for irregular layouts with ambiguous-boundary review. Define multi-row headers, blank separators, totals, units and mixed-type columns. For DuckDB, set range/header/stop policy and keep failed casts visible. [DuckDB options](https://duckdb.org/docs/current/core_extensions/excel).
3. **Test reader correctness before speed.** Build a representative fixture corpus covering date epochs, leading-zero identifiers, empty versus missing values, errors, merged headers, formulas, hidden sheets, cross-sheet dependencies and malformed input. Compare values and coordinates across independent engines on high-risk fixtures. A reported empty-shared-string misread is documented in [calamine issue #607](https://github.com/tafia/calamine/issues/607), opened 2026-02-26 and now closed; this is a regression-test lead, not evidence that every current release remains affected.
4. **Separate cached results from recalculation.** Recalculate after changes using a declared engine/version, then check outputs. Benchmark evaluation explicitly refreshes caches before openpyxl reads them. Excel and LibreOffice equivalence must be tested for the actual functions used. POI can evaluate supported functions but is not full Excel. [SpreadsheetBench recalculation workflow](https://github.com/RUCKBReasoning/SpreadsheetBench), [POI evaluation](https://poi.apache.org/components/spreadsheet/eval.html).
5. **Use deterministic data constraints.** Pandera supports dataframe schemas and custom checks, including pandas and Polars. GX Core provides Expectations and validation-result documentation. Select Pandera for validation close to a Python dataframe pipeline; consider GX for shared data-quality workflows. Add uniqueness, required fields, acceptable ranges, cross-sheet reconciliation and totals checks. Neither validates workbook visual fidelity automatically. [Pandera](https://github.com/unionai-oss/pandera), [GX Core](https://github.com/fivetran/great_expectations).
6. **Ground answers and verify edits.** Return cited sheet/cell ranges, calculation logic and explicit ambiguity; execute aggregations in a controlled runtime. For editing, evaluate target cells after recalculation and inspect unintended changes, formulas, styles/charts and workbook opening. Track region-selection, answer accuracy and editing success separately. This design follows the distinct detection/reasoning and outcome-checking stages in the research above, not a guarantee supplied by an LLM.
7. **Contain untrusted workbooks and generated code.** Bound input/archive size, elapsed time and worker memory; isolate processing and fail visibly. openpyxl recommends defusedxml for XML attacks; POI documents resource exhaustion and parser exception risks. Disable macro/external-link execution in any calculation workflow unless explicitly required. [openpyxl security](https://openpyxl.readthedocs.io/en/stable/), [POI security guidance](https://poi.apache.org/security.html).
8. **Assess operations and licensing separately from benchmark scores.** Pin libraries and transitive dependencies, review licenses for the exact artifact, verify deployment wheels/platforms, define support ownership, audit events and latency/memory budgets. SheetCopilot's repo identifies GPL-3.0; SpreadsheetBench identifies CC BY-SA 4.0. Dataset rights and code rights need separate review. [SheetCopilot](https://github.com/BraveGroup/SheetCopilot), [SpreadsheetBench](https://github.com/RUCKBReasoning/SpreadsheetBench).

Microsoft states that unattended, noninteractive Office automation is not recommended or supported and can deadlock; an unattended RPA license does not remove these operational constraints. A research benchmark using Excel COM is therefore not evidence that the same design is ready for a multi-tenant server. Consider supported service APIs where their workbook/location/permission constraints fit; otherwise explicitly own a controlled calculation environment and its limitations. [Microsoft guidance](https://learn.microsoft.com/en-us/office/client-developer/integration/considerations-unattended-automation-office-microsoft-365-for-unattended-rpa).

## Search and evidence limitations

- Performed GitHub-focused web search and unauthenticated **GitHub repository search API** queries for SpreadsheetLLM, SheetAgent and SpreadsheetBench. Search returned the official SheetAgent and SpreadsheetBench repositories; the fastexcel API query hit a 403 rate limit, so its official repo/docs were inspected through browsing. No credentials were used.
- Search API metadata observed SheetAgent pushed 2025-04-12, SpreadsheetBench 2026-03-12 and SpreadsheetBench-2 2026-10-08 (UTC timestamps). Push dates indicate repository activity, not release date, maintenance guarantees or independently reviewed correctness.
- Only primary repository authors, official documentation and author papers support the technical findings. Third-party implementation pages are cited only for their own provenance claims. No GitHub-star ranking, generic “best enterprise” label, parser championship or unverified current leaderboard winner is inferred.
- Versioned papers provide firmer dates than mutable READMEs. “Latest accessible” is not proof that no newer release, paper or private enterprise evaluation exists. This report does not provide pinned commits or package-version certification; those belong in a subsequent reproducible evaluation.
- Only this findings file was created; code/configuration and credentials were outside the research scope.
