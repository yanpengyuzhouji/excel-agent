# RC43：聊天附件内容去重复用

## 行为

- 缓存身份包含调用主体、源文件SHA256、格式、有效解析限制、解析/建库相关代码摘要和openpyxl版本。修改相关实现或限制后缓存失效，不复用旧解析缺陷。
- 只缓存自动确认成功、revision=1/version=1且无错误或严重告警的active附件。失败、处理中、人工编辑和需要严重告警确认的文件不复用。
- 命中前重新校验源文件、草稿和数据库完整性及路径，缺失或不一致时重新导入；旧工作簿不被修改或删除。
- 单进程附件导入发布锁避免两个请求同时建立同一内容。生命周期锁保护命中到会话绑定的窗口，沿用既有引用感知删除。
- 缓存表在首次启动通过create_all新增，不修改旧导入记录。失效指针退出命中，但仍保留原工作簿不可变约束；删除最后引用时移除相关缓存元数据。
- 缓存附件不可原地更新工作簿版本。需要新的解析结果时，以新工作簿上传，不改变共享证据。
- 同会话相同文件重复上传更新附件关联，不增加附件数；不同会话可各自显示上传文件名。数据目录名称以首次上传为准。
- HTTP附件响应增加布尔字段reused，前端无需更改；日志记录attachment_cache_hit及工作簿ID，不记录密钥或内容。

## 边界

只优化部署后的聊天附件上传，历史重复文件不自动迁移合并。人工低层workbook-imports接口仍独立导入。当前为单实例单进程设计，多个实例共享卷需要另做数据库租约或队列，不可仅增加worker数。每次仍有上传临时文件与hash校验I/O；复用节省的是持久副本和解析建库，不是网络传输。

不修改模型、Agent提示词或答案校验逻辑，不进行付费模型回归。已有103项组合回归通过，覆盖复用、并发、配置/读取器变化、损坏缓存、告警不绕过、共享引用删除，以及原有解析和权限边界；部署后另做真实附件HTTP验证。

RC43部署后已完成真实附件HTTP验证：同一14,441行明细附件首次上传建库15.812秒，第二会话重复上传1.328秒，返回reused=true且workbook_id一致；删除首个会话后数据保留并可读取，删除最后测试会话后共享数据清理。该耗时是本机单次样本，不是性能SLA。最终代码四项关键安全回归再次通过。测试会话已清理，用户原有会话未改动。
