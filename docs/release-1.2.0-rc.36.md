## 通用编排收敛

原observe_execution是工具状态汇总，不自动发起终稿审阅。原链路在模型首次terminate/html_interpreter时验证坐标后立即发布，缺少专门核对SQL语义与回答映射的阶段，C03的汇总粒度错误因此直接流出。

当前在引用已解析、尚未生成报告/输出答案时，自动进入一次publication_observation。使用同一默认模型、同一问题、实际SQL轨迹、已查证据和候选回答检查范围、筛选、粒度、指标、单位、时期和来源。模型可用原工具纠正或取回缓存，正确则用原动作发布。检查点每轮最多一次，没有yes/no模型裁判硬门禁、没有新业务口径、没有发布后润色或第二份报告生成。通常增加一次模型请求，仍受原预算与90秒单次调用限制；没有查询/检查证据的澄清不触发。

它增加纠错机会，不构成语义正确的数学保证。模型自检也可能漏检，因此仍按独立黄金期望验收，不允许反复重跑直至碰巧通过。

红绿重放使用实际SQLite分组计数2+3：旧链路直接输出汇总行数2，新链路在观察后允许重新SUM，输出5，并且只触发一次检查点。25项证据/Agent测试通过。此测试证明编排允许纠错，不证明真实模型一定纠错。
