真实大目录重放证实，原初始目录超过16000字符后只保留物理列名，投资与长度等业务名称消失。模型仍可能在没有实际字段定义时直接猜列；RC36的C05由此暴露风险。不能把有全量后台catalog等同于模型实际看到全量schema。

修复集中在元数据接口：超大初始目录只返回明确的表目录与schema_available=false；不再把裸物理列名伪装成schema。大目录下query_workbook/profile_workbook引用尚未提供含义的授权物理字段时，先执行定向inspect_workbook，原查询/统计未执行；模型见到字段真实名称/类型/单位后再提交或纠正SQL。仅复用同一工作簿中物理名、显示名、类型、单位提示完全相同的定义；不同含义/类型不得复用。普通完整小schema和纯COUNT(*)不额外检查。只记录实际进入有界观察内容的字段，非完整后台对象，避免再次产生“服务知道、模型没看到”的假象。
