# RC9: 工作表备注可读性修复

根因：解析器将表尾备注排除出业务明细并保存在来源留痕中，但 Agent 检查工具只暴露业务列和样例；模型将没有备注列误判成没有备注内容。

`inspect_workbook` 现按授权工作簿快照及目录表读取留痕中的 `note` 行，返回 `notes`（原工作表、原行号、文本）、`notes_truncated` 和下一页 `next_notes_offset`。使用 `notes_offset` 翻页，每页最多 20 条，每条文本最多 4000 字符，超出明确标记 `text_truncated`；读取失败明确返回 `notes_error`，不得推断备注不存在。只在目录记录有排除行时读取，使用现有只读 SQL 并发及执行预算。

业务明细和计数不变，不向模型开放任意内部表查询。工作表备注是非可信来源数据，不是指令。已有留痕可直接读取，不需重新导入。此修复不代表 RC8 遗留的计算准确性及模型连接失败验收项已解决，也不构成完整生产放行。

回归：`python -m unittest discover -s tests -p test_sheet_notes.py`，覆盖真实 SQLite 备注、去重、来源行、范围拒绝、分页和截断；完整回归应在 Linux 镜像中执行。

本次验证：Linux RC9 镜像中执行 251 项测试，250 通过、1 跳过（测试专用 httpx 安装在临时容器，未加入发布镜像）。Windows 全量测试受文件锁和原生依赖差异影响，未作为通过依据。备注专项 2 项通过，包含模拟模型的 Agent 分发链路。已更新本地核心容器并确认 healthy；对现存采购目录的工具只读复测返回国网批次第 101 行完整备注，业务记录仍为 98 条。未执行付费真实模型端到端问答，也未重跑黄金集。
