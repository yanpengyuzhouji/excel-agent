# 1.2.0-rc.1 服务能力验收

这是独立Excel核心API候选版，不代表业务负责人已确认全部答案，也不代表
Spring Boot的用户权限已验收。共享匿名空间保持不变，禁止直接作为公网多租户入口。

## 固定交付物

- Compose镜像标签：`excel-workbook-service:1.2.0-rc.1`。
- 基础镜像固定digest，Python运行依赖见`requirements.lock`。
- `/api/v1/health`及OpenAPI返回软件版本；不向用户引入附件“版本”概念。
- 验收以实际image ID为准，标签本身可被覆盖，不能替代digest。
- 系统原生库未做Debian快照锁定；正式交付应保存已验收镜像或按digest分发，
  不承诺未来重新构建得到相同二进制。不得把`.env`、业务文件、测试证据打进镜像。

## 修复范围

1. 工具上下文不再按字符硬截JSON，保留紧凑表映射，明确样本/字段省略。
2. 压缩软目标不再误作硬拒绝线；真实超出强制上下文或总预算时仍拒绝。
3. Agent不读取内部元数据表，避免把完整导入清单再次送给模型；原始SQL证据
   仍可按result_id读取。控制状态仅带有限个近期证据索引，完整轨迹不删除。
4. 无正文的空响应/仅推理响应最多恢复一次，共享原调用总时限；首正文仍为10秒。
   已输出文本、鉴权、限流、输出截断等情况不自动重放。不承诺供应商永不失败。
5. 强化单位、分母、范围及去重口径提示。对明确的`SUM(H*N)/SUM(N)`且源字段单位
   唯一的情况做窄范围单位归一并显示单位校验；不改变数值，不泛化处理其他公式。

## 资源与部署边界

单实例2CPU/2GiB，导入并发1、Agent并发2、SQL并发4，超限429并提供Retry-After。
每文件各表累计最多60万格，行/列/文本/ZIP膨胀等保护继续生效。10万行上限包含
表头；合成CSV边界样本是99,999条明细加1行表头、6列。200MB是上传拒绝上限，
不是已验证的任意200MB复杂XLSX处理承诺。不要把多个副本接同一SQLite卷扩容。

## 验收协议

- 目标Linux镜像内完整单元/接口测试，不用Windows缺库或文件锁结果替代Linux验收。
- `scripts/accept_release_ops.py`在独立临时容器/卷执行容量、超限、并发、持续流式
  请求、重启、强制终止及恢复验证。模拟模型只验证执行基础设施，不验证模型准确性。
- 强制SIGKILL不是OOM模拟；报告必须保留OOMKilled状态，不能混为已通过OOM验收。
- 最终镜像连续执行至少两轮完整64题真实DeepSeek回归，包含复杂比较/计算、跨附件、
  连续追问和3份报告；逐轮保留首次结果，不用独立重试覆盖。内部空响应恢复要单列统计。
- 对全部报告检查实际HTML/PDF数值、前端历史预览、下载和PDF分页。
- 自动筛查与人工语义复核分开；未完成的业务签字、长时间生产运行验证须明确列为待办。

## 回滚

保留此前image ID及整个数据卷备份；本版本未引入数据库结构迁移。回滚使用已保存镜像
启动，不执行`down -v`。升级/回滚前停止写入并备份全卷；恢复到独立卷先验附件、会话、
SQL与报告。不能一边运行SQLite一边逐文件复制充当一致性备份。
