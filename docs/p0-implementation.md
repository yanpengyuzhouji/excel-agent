# P0 解析加固交付记录

基线：`3314a5e`（用户已推送的当前版本）；范围见 `excel-enterprise-readiness-2026-10-15.md` 的 P0。原快照标签 `snapshot-2026-10-15` 不变。

## 已实现

- 编号按文本保留；数值推断使用 Decimal，建库 INTEGER 不经 float，拒绝截断、溢出、非有限数和有意义的 REAL 精度损失。
- 源单元格的原始值、缓存值、类型、坐标与数字格式保存于草稿及 `_dbgpt_source_cells`。数字另保留 OOXML 原始值/类型；日期保存原始序列及 1900/1904 日期纪元，与解码值区分。支持明确简单格式的显示值；未实现的自定义显示格式记为未知，不伪造渲染结果。源文件始终保留。
- 小表按明确字段识别；完全重复的表头、明确汇总和备注行单独留痕，排除口径需要确认。
- 对检测到的并排/上下多个表区和未验证的多级表头阻止自动建库。不是任意复杂 Excel 的完整解析器；不确定布局要求整理或确认。
- 确认前复核源文件 SHA-256；入库事务提交前对账业务值、行坐标、类型、表结构、源事实、lineage、metadata 和 manifest；不一致回滚，未通过的数据库不激活。
- 公式缓存缺失与有值但未经重算验证分别告警；公式错误值告警；主解析器失败停止导入，不静默降级。
- 目录/Agent 可读取单位提示、数字格式、源记录与排除行数，明确 REAL 汇总是近似计算。

## 不做的操作及边界

- 不自动改写已有附件和数据库，不迁移用户历史或重算源文件公式，不调用云模型验证。
- 不将“缓存有值”视为最新，不将 SQLite REAL 视为 Decimal 财务引擎；不会自动猜测金额单位。
- 自定义复杂显示格式保留 format 和原始值，但不承诺复现 Excel 显示。
- 仍需企业真实脱敏文件黄金集、解析进程隔离和资源压测等 P1 验收，不能据本次改动宣布企业发布完成。

## Standards

没有单独的项目规范/代码气味阻断项。初审提出的合并编号格式不一致、旧合并草稿兼容、大数字显示异常三处正确性问题，均补回归后修复；独立复核确认三处不再阻断。

## Spec

初审提出四项：编号显示舍入改变值、表头前业务表漏覆盖、表头覆盖参数绕过结构保护、日期解码值冒充原始序列。均添加针对性测试并修复。复核还发现元数据识别可遮蔽前置表，已追加字段型表头判断，禁止静默建库。

本轮双轴汇总：Standards 独立规范项 0；Spec 初审缺口 4 项。最严重的是前置表漏覆盖，已增加源区域分类与阻断，仍不承诺自动理解任意业务布局。
