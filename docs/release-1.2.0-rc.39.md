## 收敛内容与已知边界

1. 大目录只负责找表。字段含义被省略时，先定向取得真实字段映射再执行拟提交的SQL/profile；同一工作簿的完全相同定义可复用。避免“后台有schema，但模型只看见物理列名”。不保证模型读后必然理解正确。
2. 发布前一次有界observation，不是yes/no模型裁判硬门禁。检查实际SQL、数据范围、指标、单位和引用；缺少派生值时继续工具计算，不心算。通常增加一次模型调用，不循环自审。
3. 分组占比使用shares统一求所选完整数据集分母；任意两项或已存总计仍用ratio。所选范围和是否混合汇总行仍由调用方负责，工具不猜业务口径。
4. 期间总额/差额/增长率优先compare_totals原子返回同一输入的整组结果；修正范围后整组重算。保持独立difference/growth_rate能力，不按业务词硬路由。
5. 执行状态的calculations补齐来源ID、计算推导/操作数、结果预览、单位和完整性标记；不再仅列“已完成”。预览最多3行、推导有界，省略明确标记，不把截断摘要当完整证据。不简单废弃所有旧计算，因为不同合法子组可以同时存在。
6. 保留确定性安全/资源/快照/循环保护；精确投影支持独立源列排序；Decimal精度检查隔离调用者已有标记。未恢复全文数字扫描、强制预计划或按题号修正答案。

观察和工具可降低错误自由度，不是任意业务语义的数学证明。验收通过只能证明本批次覆盖的行为，不承诺未来任意Excel、问题、供应商版本都零错误。
