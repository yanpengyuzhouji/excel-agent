# RC33：固定输入计算的循环保护

日期：2026-10-17。状态：通用去重缺陷修复并部署，真实R02定向已结束，内容仍不合格，不完整放行。

## 实际根因

RC32 DeepSeek报告题连续13次计算相同baseline/current缓存坐标。原guard把计算结果总数加入去重上下文，每次生成aggregate-N就使下一次相同调用成为“新上下文”，完全绕过去重，消耗接近200k运行预算后报mandatory context不足。

排除了“参数每次不同”和“原输入变化”：执行记录中operation、result_id、row、column均一致；输入是只读版本快照的缓存值。不是按题号、业务字段或固定答案猜测的缺陷。

## 修复与回归

- 显式引用：去重上下文只取实际依赖的结果ID及其是否已到达；新增无关输出不重置去重。原先未知ID后来可用时，合法重试仍允许。
- 旧版无显式引用的调用：跟踪实际“每工作簿最新查询ID”，不把计算输出数量误判成输入变化。
- read_query_result仍允许压缩后重新取缓存；observe_execution随执行状态更新；其他循环/重试策略不变。
- 最小Agent重放测试在旧逻辑失败（1 != 4），修复后相同差额只执行一次，随后三次重复被阻止并安全终止；不会伪造成功结果。另测试依赖到达、无关输出与隐式最新查询变化。
- 本机24项证据发布/Agent测试通过。Windows另一个Catalog测试受沙箱临时目录SQLite权限限制失败，未把该环境错误当作产品失败；最终Linux隔离369项测试：368通过、1字体条件跳过（rc33-unit-linux.json）。
- 最终镜像sha256:c3515a55fc08e531310c36fb211d751fd637776403681c2fe281bb6c3888aef2，54个部署文件哈希一致（rc33-runtime-source.json）。保留思考30秒、非思考10秒、单次总90秒。
