# 工作簿目录完整性修复

黄金验收发现：月度报表可通过 SQL 查询，但 Agent 获得空表目录。根因为 catalog_json 在序列化之后按 80,000 字符截断，形成非法 JSON；读取时异常被替换为空对象。文件路径和源数据本身未丢失。

修复包括完整保存结构化 JSON、保留搜索文本的长度限制、读取时检查目录结构。即使 active_import_id 未变化，旧损坏目录也会从活动数据库重建。无法重建时明确返回目录不可用错误，避免作为“没有数据”交给模型。已有数据库和附件无需重新上传来修复目录；这与解析器修复需重新上传不同。

回归测试 `tests/test_catalog_integrity.py` 覆盖超过 80k 的真实结构序列化、相同活动版本的损坏目录修复，以及修复失败时明确报错。修复前 3 项均失败，修复后与范围、附件和结构化解析回归合计 43 项通过。

已重建容器；真实月度报表目录为 105,535 字符、14 张表，JSON 有效。HTTP 黄金验收新增 Agent 目录表集合与数据库表集合的一致性检查。

模型回归脚本默认使用 deepseek-v4-flash 选择项，实际服务配置模型为 deepseek-flash；可显式指定 `--model Qwen3.8-27B-ModelScope`。这不修改旧会话保存的模型，不删除现有模型选项。测试结果保存在私有黄金集 runs 目录，每轮独立归档。

本次同时改变了服务代码与验收模型，因此不能把前后结果差异全部归因为模型强弱。原有 10 秒正文等待限制等模型超时设置保持原配置。
