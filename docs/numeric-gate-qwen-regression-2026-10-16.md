# 数字计算门禁专项回归：Qwen3.8-27B

## 结论

当前 RC13 门禁明显偏保守，且存在独立于模型的编号格式破坏。它能拒绝未引用/越界/伪造的数值发布，却不能仅凭引用保证单位、业务口径及所有计算精度正确。不建议把当前实现作为通用问答的全面强制门禁直接放行生产；应先修复类型保真与校验范围，再用同题集复测。

本次仅构建测试并评估，没有修改应用代码、模型配置或容器。没有把失败题重跑成成功，没有改动生产门禁；当前运行镜像仍为 RC13。

## 关键发现

### 1. P0：服务端填值改变文本编号，不是模型或解析器丢失

B01的 SQL 结果为字符串 `"00001"`，`numeric.validated` 却记录 `rendered="1"`，最终答案也是 `1`。编号读入正确，错误发生在 `render_numeric_answer` 将纯数字字符串转 Decimal 并重新格式化的环节。

影响还出现在B02/B07的附带记录标识，及A12报告要求原样列出的全部id：`00001..00008`变成`1..8`。A12的金额、记录数、PDF下载均通过，并不能证明报告原始文本正确。

### 2. P0：全段扫描把普通文字和拒绝说明当成计算

- B03/B05/B11：日期、型号、备注读取本身正确，但最终润色周边的 `id为00001` 等文字被拦，且不进入可纠正通道。
- B06/B08：真实原文包含“合计2025元”“合计3类设备”，被当成新的统计结论。B08备注已由工作表检查工具读到，不能把失败归因于解析不到备注。
- B12：版本号 `v1.2.3`、原文数字与否定表达“不求和”影响触发；源版本标签按字符串替换还会将版本的一部分遮掉，剩余数字再被拒绝。
- N05：已查到完整总额，解释“前两条样本”中的“两条”仍被当成未引用计算值。
- A08/A10/N03/N04：零基期、NULL、公式常数100、否定0%、否定用户错误数字都会增加误拦或纠正。
- C06：`保留 2 位小数`含空格，被不同于`2位小数`的字面规则拦截，另有模型列引用错误。

因此当前不是只约束计算指标，而是把编号、原文、公式说明、否定引用和格式描述一起绑进了数值协议。简单继续加白名单不能解决类型与意图的问题。

### 3. P0/P1：引用正确，不等于单位和业务结论正确

C04要求元换成万元，正确答案为 `0.1000万元`。模型只查询并汇总出 `1000元`，最终引用1000却标成`1000.0000万元`，门禁放行。它验证了数值来源，没有验证单位转换；结果相差10000倍。

这属于当前门禁范围的明显缺口，不应以“已通过 numeric.validated”展示为业务计算全面正确。

### 4. 复杂合法计算会被迫做无意义补算

C01正确CTE总额被外层别名识别拒绝，再补算后通过。B10只是读取已有total_metric，却被要求满足sum类型，最终对已筛出的一行再次求和。B09使用英文`avg_metric`描述能通过，而离线同值中文“平均值”描述会被拒绝，说明判定受措辞影响。

### 5. 精度保护有作用，但未覆盖SQL REAL

C05使用受控十进制比较，正确给出大额差额 `0.010000000000`，说明计算工具是有价值的。

A09目标负基期差额50/增长率-50%正确，但额外展开全部场景，把SQL浮点结果 `0.19999999999999998`、`0.010009765625`、`0.004999999999999893`直接发布。这些引用确实来自SQL，门禁不能自动恢复原始十进制意义。A09归为有条件通过，不能把额外表格当成精确十进制验收。

## 离线门禁探针：18项

8项预期非法的发布输入全部被拒绝，包括未引用字面量、错误字面量、未知/越界引用、差额与增长率互换、截断证据、常量SQL冒充业务总额和纯数字来源名绕过。

10项预期合法的表达中，6项被拒绝：原始平均值、原始总额、CTE外层投影、换算后总额、备注原文、缺数据拒答。该组是针对已知边界设计的机制探针，不是随机流量，不能将60%直接称为线上误拦率。完整输入及判定在 mechanism-probes.json。

## 建议的修复顺序（本轮未实施）

1. **P0 类型保真**：文本编号/版本/规格/日期保持原字符串；只有明确的计算结果才能进行Decimal舍入格式化，禁止对原始编号按“看起来是数字”转数值。
2. **P0 缩小门禁**：按计算指标与引用声明校验，而不是扫描整段所有数字。区分统计计算、原始字段读取、原文引用和解释；否定表达、无数据说明不应强制补出汇总值。不要用更多特例白名单掩盖问题。
3. **P0/P1 单位与来源语义**：计算结果携带单位、公式、基期/本期、筛选范围；单位换算使用工具执行并返回目标单位，答案单位由结果元数据生成。
4. **P1 计算列血缘与精度**：正确识别CTE/窗口/已有指标，避免为满足类型做无用SUM；金融差额/增长率优先受控十进制或定点数路径，不把SQL REAL尾差作为精确金额。
5. **P1 统一纠正/错误协议**：最终润色校验也应有一致错误码和有限纠正机制，但不单纯增加重试次数；先消除误触发，再控制耗时与模型调用。
6. 修复后冻结同一题集，再用相同Qwen配置执行独立新轮次；本轮没有同题DeepSeek或门禁关闭对照，不能据此宣称Qwen总体弱于DeepSeek，也不能给出严格的门禁开关因果收益。
