## 本轮必要修复

1. 上下文：工具观察保留合法JSON与表映射，限制单次观察和近期证据索引；
   必须上下文实际装得下时，不再被60%压缩软目标误拒绝；Agent禁止读取内部元数据表。
2. 模型：无正文最多一次恢复，受原时间/调用/Token预算约束；空白不算正文，
   已输出正文不重放。DeepSeek控制阶段使用JSON对象并显式关闭默认思考模式；
   最终回答仍逐字输出。不执行私有推理内容。
3. 口径：明确单位、加权分母、汇总与分组、计划年份等范围，保留原始精度；
   仅对明确且唯一的加权公式单位契约做窄范围归一，不声称具备通用数学验证器。
4. 收尾：多工作簿和通用问答先保存预算、上下文并释放名额，再发done/error；
   断连由幂等收尾兜底，避免立即追问/删除仍被上一轮阻止。
5. 发布：基础镜像摘要固定、Python依赖精确锁定；服务健康接口包含软件版本；
   导出镜像并保留摘要、测试首次结果、原始SSE、模型调用安全元数据与恢复记录。
6. 工具协议：兼容已知参数位于JSON顶层或action_input中，不静默丢参；两层冲突时拒绝。
   保留动作白名单、授权源与只读SQL校验，不替模型补造SQL。

## 使用边界

- 默认单实例2CPU/2GiB，禁止多个副本直接共用同一SQLite卷。
- 全工作簿累计60万格、每表10万行含表头、512列；复杂样式/大范围稀疏表仍可能更耗内存。
  200MB仅是上传上限，不是任意200MB文件的处理承诺；接近容量上限需先用实际文件压测。
- 本轮真实样本认证XLSX/CSV；解析器兼容XLSM不等于本轮已覆盖真实宏工作簿。
  不支持旧XLS/WPS ET，先转换，不运行宏。
- 本轮认证DeepSeek；保留的其他模型配置不是已验收模型。
- 按用户要求保留共享匿名空间。正式接入仅允许可信后端访问，由Spring Boot逐次授权会话。
- 无可靠断线续传/任务取消、跨副本协调、自动TTL。客户端不能盲目重发问答POST。
- 恢复方案为停服全卷一致性备份；本轮演练不等于已建立自动备份计划或生产RPO/RTO承诺。
  故障注入针对已完成导入的数据，不代表已覆盖导入事务中途断电；OOM后由测试脚本重启，
  不把数据恢复成功表述成生产自动恢复时限已达标。
